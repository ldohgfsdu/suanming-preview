# 01 · 项目总览

## 1. 项目定位

**东方时间文化档案** 是一个微信小程序。用户输入出生日期、时间与出生地，
小程序在本地用**天文历法算法**现算一份「历法档案」：四柱干支、前后节气、农历日期、
月相月龄、五行字面计数、真太阳时修正量。随后用户可**显式点击**生成 AI 文化背景说明，
或把档案保存为图片卡片。

它不是算命工具。产品边界由《PRD v1.2》§1.2 / §13 P2 Never 冻结：

| 做 | 不做 |
|---|---|
| 公历/农历日期互查、干支历标注 | 算命、占卜、算卦、排盘 |
| 24 节气精确时刻、月相、日出日落 | 吉凶、宜忌、运势、流年、大运 |
| 真太阳时均时差校正 | 合婚、择日、化解、开运 |
| 传统文化与历法知识科普 | 五行旺衰/喜用神判断、十神、藏干、神煞 |
| 可复现、可验证的确定性事实 | 性格/事业/财运/婚姻/健康类个人断言 |

## 2. 产品形态：七页 IA + 科普增量

实际代码中的 8 个页面（`miniprogram/app.json:2`）：

```
pages/index/index    首页：输入日期/时间/性别/地点 + 今日天时卡片 → 生成档案
pages/result/result  档案页：展示全部历法事实 + AI 文化解读 + 保存分享卡片 +
                     就地科普 ⓘ（四柱/农历/真太阳时/五行/节气/月相旁就地展开）
pages/today/today    今日天时：干支、节气、月相、12 时辰表、日出日落 + 就地科普 ⓘ
pages/terms/terms    全年节气历：指定年份 24 节气时刻（按四季分组）
pages/history/history 历史档案：本地存储的档案列表，可复用/删除/清空
pages/about/about    关于 / 免责声明 / 算法说明（纯静态合规页）
pages/culture/culture            传统文化科普库：19 条条目检索 + 分类筛选
pages/culture-detail/culture-detail 科普条目详情：定义/渊源/数据表/关联概念
```

> 注 1：冻结规格中的七页 IA 含独立 Transparency 页，当前实现中该部分内容并入
> `result` 与 `about` 页 —— 这是 `PREVIEW_STATUS_AUDIT_2026-10-04.md` 登记的已知偏差。
>
> 注 2：`culture` / `culture-detail` 两页是科普定位（「主打科普」）下的**增量扩展**，
> 不在冻结七页 IA 之列；知识库文案受 `tests/unit/culture-data.test.mjs` 的
> PRD §1.2 禁词扫描与引擎一致性断言约束，页面无任何计算与网络。

## 3. 核心能力清单

### 3.1 范围与精度

| 能力 | 实现口径 | 精度 |
|---|---|---|
| 日期范围 | 公历 1900–2100（首页选择从 1901 起） | 算法边界测试覆盖 1900/2100 极值 |
| 节气时刻 | VSOP87B（地球 L/R 级数）+ 岁差 + 1980 IAU 63 项章动 + 光行差 + FK5 改正，二分求根 | 2026 年 24 节气 **24/24 日期正确，时刻偏差 ≤1 分钟**（对紫金山天文台） |
| 均时差 EoT | 年积日三角函数级数 | ±17 分钟量级，满足文化展示 |
| 日月位置 | 高精度太阳视黄经（含 ΔT → TT 换算） | ΔT 用 Espenak & Meeus 分段多项式 |
| 真太阳时 | `offset = EoT + 4 × (lon − 120)` 分钟 | 分钟级 |
| 日出日落 | NOAA 通用算法（赤纬 + 时角 + −0.833° 折射补偿） | ±1 分钟 |
| 农历 | 构建期生成的朔月表（Meeus 朔 + 中气定闰） | year/month/leap 与黄金锚点对拍通过；day 在朔近日夜有 ±1 边界并显式标 `approx` |
| 月相月龄 | Meeus 新月级数，按**出生绝对瞬间**计算 | 天级 |
| 中国夏时制 | 1986–1991 硬编码政府文件确认的 12 次切换 | 逐年真实日期，不套「第 N 个周日」公式 |

### 3.2 历史墙钟时间（1986–1991 夏时制）

生产生成路径已接入 V4 closure：

- **GAP（拨快跳过）**：`02:00–03:00` 历史上不存在 → **拒绝并提示用户返回修改**，不静默猜测
- **FOLD（拨回重复）**：`01:00–02:00` 出现两次 → **必须由用户显式选择「第一次/第二次」**
- 选完后换算为**标准北京时间（UTC+8）绝对瞬间**，再进入真太阳时换算
- 数据源为政府文件原文交叉核对（含 1988-04-17 的百度百科误载纠正）

### 3.3 出生地点

- 不调用定位 API（`wx.getLocation` 完全不出现），地点来自内置名称表或用户手动经度
- UI 覆盖省/市/区县三级名称；**计算坐标是所属地级行政中心近似坐标**
  （数据源：民政部码 + 阿里 DataV areas_v3 centroid）
- 临界输入（接近时辰边界）可在高级设置手动填经度（限定东经 73–135°）

### 3.4 AI 文化解读

- 必须用户显式点击；客户端 8 秒超时即降级
- 服务端要求 OPENID（拒绝未鉴权）、严格 facts schema 校验、服务端 SHA-256 文档指纹、
  按 `docHash + promptVer + model + outputVersion` 缓存、输出 Guard
- Guard 失败带修复提示重试**恰好 1 次**，仍失败返回 `fallback:true`
- 客户端保留「本次小程序会话」级缓存（避免跨会话误用旧模型内容）

## 4. 隐私与数据

| 项 | 事实 |
|---|---|
| 定位 API | **未调用**；门禁脚本递归扫描生产源码中的 `wx.<locationApi>()` 真调用 |
| 权限声明 | 仅 `scope.writePhotosAlbum`（保存分享卡片到相册），`app.json:21` 声明用途 |
| 历史档案 | 保存在**设备本地** `wx.Storage`，key `eastTime.history.v2`（兼容读 v1） |
| 个人信息收集 | 无。云函数只取微信上下文 OPENID 用于配额归属 |
| 客户端自报 docHash | 服务端**不接受**为可信事实指纹，自行对规范化 facts 重新计算 |

## 6. 上游关系

本仓库是 **Suanming Core**（Kotlin/JVM，`_handover/Suanming-source-v0.21.0/`）的
「比赛轨」浅验证入口。Core 中被移植到 JS 的部分：

| Core 模块 | 移植到 |
|---|---|
| `domain-solar-time`（真太阳时、夏令时、降级契约） | `miniprogram/lib/chinadst.js` + `civilTime.js` |
| `domain-solar-term`（VSOP87D 节气、ΔT） | `miniprogram/lib/solarlon.js` + `engine.js` |
| `domain-calendar`（农历、朔望） | `miniprogram/lib/lunar*.js` + `archive.js` 新月级数 |
| `domain-bazi`（四柱、日界） | `miniprogram/lib/archive.js`（五虎遁/五鼠遁） |

但 Core 的 `Rule → Claim → CompositeClaim → Renderer → Presentation` 解读链路
被 `calculation-baseline-v1.json` 的 `out_of_v1` **显式排除** ——
Preview 的 AI 知识源必须是新建资产，不得假借 Core 规则包。
