# 09 · 运行、构建与部署

## 1. 环境要求

| 项 | 要求 | 固定方式 |
|---|---|---|
| Node | **18.20.4** | `.nvmrc` + `package.json#engines.node` 双固定 |
| npm | 随 Node 18 | 锁文件安装（`npm ci`） |
| TypeScript | 5.4.5（精确） | `devDependencies` 无 `^` |
| 微信开发者工具 | 任意支持基础库 3.6.2 的版本 | 人工安装 |
| JDK 17 | 仅 Core 回归 / Kotlin 对拍需要 | `~/.workbuddy/binaries/jdk` |
| kotlinc | 仅跨语言对拍需要 | `~/.workbuddy/binaries/kotlinc` |

### 本机工具链对准（Windows）

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-env.ps1
```

把 `~/.workbuddy/binaries/` 下的 Node 18.20.4 / Git / JDK / kotlinc 插到当前 shell PATH 最前。
**每个新 shell 都要先跑**（或加入系统 PATH）。

## 2. 安装

```bash
npm ci
```

`preinstall` 钩子会自动跑 `node scripts/check-node-version.mjs`。
Node 主版本不对会在**装依赖前**就直接失败。

> 为什么必须 `npm ci` 而不是 `npm install`：仓库靠 `package-lock.json` 保证
> `typescript` / `eslint` 等工具链版本可复现；`npm install` 会改写锁文件。

## 3. 唯一门禁入口

```bash
npm run gate
```

顺序**固定**（`scripts/run-gate.mjs`）：

```
1. Node 版本守卫          scripts/check-node-version.mjs verify-node
2. 隐私字段自检          scripts/check-appjson-privacy.mjs
3. TypeScript typecheck  tsc --noEmit -p tsconfig.json
4. ESLint                eslint .
5. 测试构建 - 清理       scripts/_clean-dist.mjs
6. 测试构建 - 编译       tsc -p tsconfig.test.json
7. TS 单测               node --test --experimental-vm-modules dist-test/tests/unit
8. mjs 单测              node --test --experimental-vm-modules tests/unit
```

退出码：`0` = 全部门禁通过；非 0 = **首个失败环节的退出码**，后续环节不执行。

### 为什么门禁自己解析 Node

开发机可能同时存在多个 Node。npm 在 Windows 上运行 scripts 时会把自己的 node 目录
插到子进程 PATH 前面，导致门禁子进程误用另一个 Node。
因此 `run-gate.mjs` 不再让子进程自己解析 `node`，
所有步骤都直接用 `process.execPath`（或 `SUANMING_NODE_BIN`）启动。

```bash
SUANMING_NODE_BIN=/path/to/node node scripts/run-gate.mjs   # 特殊本地工具链才需要
```

## 5. CI（GitHub Actions）

`.github/workflows/ci.yml`，触发条件 `push` / `pull_request` 到 `main`：

```yaml
env: { TZ: UTC, LANG: C.UTF-8, LC_ALL: C.UTF-8 }
steps:
  1. actions/checkout@v4
  2. actions/setup-node@v4  (node-version: 18.20.4, cache: npm)
  3. npm ci
  4. npm run gate 2>&1 | tee gate.log
  5. always() 上传 gate.log 工件（保留 7 天）
  6. PR 失败时用 github-script 把日志尾部 12000 字符回写为 PR 评论
     （marker: <!-- suanming-gate-diagnostic -->，重复评论走 update）
  7. always() 打印环境指纹（NODE / INTL_LOCALE / TZ / tsc -v）
```

**CI 只调用这一套门禁，不再维护第二份流程**（这是 2026-10-08 的显式收敛）。

## 6. 在小程序开发者工具中运行

1. 打开微信开发者工具 → 导入项目，目录选 `suanming-preview/miniprogram/`
   （**不是仓库根** —— `project.config.json` 在这里）

## 7. 部署云函数

权威副本：`miniprogram/cloudfunctions/insight/`

```
miniprogram/cloudfunctions/insight/
├── index.js        云函数主逻辑
├── model-policy.js 错误分类/重试/脱敏
├── package.json    依赖声明
└── config.json     权限配置
```

步骤：

1. 修改**只**改 `miniprogram/cloudfunctions/insight/` 下的文件
2. 把改动同步回仓库根 `cloudfunctions/insight/`（`tests/unit/insight.test.mjs` I12 强制 `index.js` 逐字节一致）
3. 在开发者工具中右键 `miniprogram/cloudfunctions/insight` → 「上传并部署：云端安装依赖」
4. 确认部署参数（`cloudbaserc.json`）：

```json
{
  "envId": "cloud1-d5ggz0479e06a5688",
  "functions": [{
    "name": "insight",
    "timeout": 20,
    "memorySize": 256,
    "runtime": "Nodejs16.13",
    "envVariables": {
      "INSIGHT_MODEL": "deepseek-v4-flash",
      "INSIGHT_RATE_MINUTE_MAX": "6",
      "INSIGHT_RATE_DAY_MAX": "40",
      "INSIGHT_CACHE_TTL_MS": "86400000",
      "INSIGHT_CACHE_MAX": "128"
    }
  }]
}
```

> `runtime: Nodejs16.13` 是平台侧事实。升级前必须先验证平台支持与 SDK 兼容性
> （仓库自身工具链是 Node 18.20.4，二者不是同一运行时）。

## 9. E2E 终验（不入门禁）

单套直跑（IDE 已开着项目、已知自动化 ws 端口时）：

```bash
set WX_WS_PORT=<自动化 ws 端口>    # 不设则读 .tmp-bridge-result.json，再退默认 9420
node tests/e2e/culture-e2e.mjs     # 科普列表/详情两页 E2E（6 项）
node tests/e2e/wechat-e2e.mjs      # 主链路 E2E（12 项）
```

推荐用编排器一键全新拉起（杀旧 IDE → 动态选自动化端口 → 重试 + 稳定性门 → `cli.bat auto`
→ 按序跑全部目标 → 收尾清理；日志写 `.tmp-orch.log`）：

```bash
node scripts/tools/e2e-orchestrator.mjs tests/e2e/culture-e2e.mjs tests/e2e/wechat-e2e.mjs
```

2026-10-15 冷启动实测：culture-e2e 6/6 PASS（exit 0），wechat-e2e 11 PASS + 1 BLOCKED
（T9 云端模型 429 限流，外部阻断非代码缺陷），全程约 3.5 分钟。
自动化 ws 端口由 `cli auto --auto-port <空闲端口>` 绑定，**不能与 IDE HTTP 端口（9420）相同**——
同端口时 ws 升级会被 HTTP 服务拒掉；App.* 应用层 RPC 需等页面真实渲染（appservice 发出
`App.initialized`）后才可用。

退出码含义：

| 码 | 含义 |
|---|---|
| 0 | 全 PASS |
| 1 | 有 FAIL（编排器聚合：立即停止后续目标） |
| 2 | 仅 BLOCKED（外部阻断，如 provider 429；编排器继续跑完后续目标，有 FAIL 时以 1 为准） |

覆盖：夏时制 GAP/FOLD、23 点日界、真太阳时跨时辰/跨日、历史 v2 重新生成、
AI 本地/8s 超时降级与云端成功、分享卡 → 相册、深色模式、分享深链；
科普两页的列表真实渲染、真实输入检索、分类筛选、详情装配、关联跳转与无效深链兜底。

## 12. 排障速查

| 现象 | 首选排查 |
|---|---|
| 门禁报 `Node 版本不对` | 先跑 `scripts/setup.ps1`；或 `SUANMING_NODE_BIN` 指定 |
| 门禁报 `MODULE_NOT_FOUND` | 大概率是 Node 版本用错（门禁注释明确指出这是版本错的伪装症状） |
| AI 永远是「本地规则」 | ① `app.js` 的 `cloudEnvId` 是否为空 ② 云函数 timeout 是否过小 ③ CloudBase 计费模式是否仍是旧配额制 |
| AI 返回 `unauthenticated` | 云函数 `cloud.getWXContext()` 拿不到 OPENID —— 检查是否真从微信小程序上下文调用 |
| `invalid_facts:…` | 客户端 `buildFacts` 与服务端 `validateFacts` 白名单不一致；先看服务端 `console.error` 日志 |
| `hourPillar` 相关运行时报错 | 检查 `import-contract.test.mjs` 是否通过（2026-10-08 曾有导入错位） |
| 云函数改了没生效 | 是否忘了同步回根 `cloudfunctions/insight/`（I12 会失败） |
| 农历日期差一天 | 朔日边界 ±1 是已知真实历法误差，`arc.lunar.approx === true`；不是 bug |
