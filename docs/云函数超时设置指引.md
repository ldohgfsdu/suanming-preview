# 云函数超时设置 · 必须手动改一次

> 2026-10-06　|　**这是「本地规则」降级最可能的根因**

---

## 问题

云函数 `insight` 的 **timeout = 3 秒**，但大模型调用通常需要 **5–15 秒**。

结果：模型还没返回，云函数就被平台强制掐断 → 客户端收到失败 → 自动降级为「本地规则」。

> 这解释了为什么你看到的是「本地规则」而不是「AI 生成」——
> 云函数本身部署成功了（状态 `Active`），但它**没有足够时间执行完**。

---

## 解决：把超时改成 60 秒

### 方法一：云开发控制台（推荐，可视化）

1. 开发者工具 → 顶部「**云开发**」
2. 左侧「**云函数**」→ 点 `insight`
3. 找到「**超时时间**」设置项
4. 改成 **60 秒**（或最大可设值）
5. 保存

> ⚠️ 若控制台限制最大 60 秒，填 60 即可。

### 方法二：重新部署时指定

部分版本的 `config.json` 支持 `timeout` 字段，但**实测 deploy 命令不采用**（已验证：写入 `"timeout": 60` 后重新部署，`info` 仍显示 3）。所以请用方法一。

---

## 客户端已做的调整

`miniprogram/pages/result/result.js`：

```js
// PRD 冻结性能红线「AI 8s 降级」（PRD:170/289）
const INSIGHT_TIMEOUT_MS = 8000;
```

> **客户端等待固定 8 秒，这是 PRD 冻结红线，不要改大**（改 65s 曾被审查报告列为硬违反）。
> 8 秒未回 → **本轮降级为「本地规则」文本**（本地 `ruleBasedInsight`，瞬时可出、永远有内容），
> 绝不会显示「暂不可用」；晚到的云端结果本轮不采纳，只补写缓存，下次进同一档案直接命中。
>
> 因此**云函数 timeout 仍必须调大**（见上）：客户端只等 8 秒，若云函数 3 秒就被平台掐断，
> AI 永远赶不上这 8 秒，用户看到的就永远是「本地规则」。
> 模型需在 8 秒内返回才能被采纳为「AI 生成」。

---

## 验证

改完超时后重新生成档案，看结果页「历法文化解读」区块：

| 显示 | 含义 |
|---|---|
| **「AI 生成」** | ✅ 成功 |
| 「本地规则」 | ❌ 仍未生效，看下方排查 |

### Console 日志

已在解读加载处加了诊断日志：

```
[insight] cloudReady = true | env = cloud1-d5ggz0479e06a5688
[insight] 云端 AI 成功
```

或降级时：
```
[insight] 走本地规则降级，原因： timeout
```

**原因对照表**：

| `reason` 前缀 | 含义 | 处理 |
|---|---|---|
| `local_default` | 未配置 EnvId | 检查 `app.js:7` |
| `timeout` | 超时 | **调大云函数超时**（本文） |
| `guard:` | 输出未过 Guard | 看具体项，多为 AI 输出了禁词 |
| `error:...` | 调用失败 | 看具体错误 |
| `bad_result` | 返回结构不对 | 检查云函数是否部署成功 |

## 若调超时后仍是「本地规则」

依次排查：

1. **云开发是否开通 AI 能力**
   云开发控制台 → AI → 确认已开通（混元/大模型调用需此权限）

2. **看云函数日志**
   控制台 → `insight` → 日志，看真实报错

3. **确认模型可用**
   某些环境需在云开发控制台先「开通 AI」才能调`app.ai().model()`

---

**一句话**：云函数状态 `Active` 只说明部署成功，不代表能在 3 秒内跑完模型。超时必须手动调大。
