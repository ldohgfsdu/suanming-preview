# 11 · 治理与文档索引

本仓库不是「代码 + README」结构，而是**冻结规格 + 治理裁决 + 执行证据**三层文档体系。
理解代码前必须先理解「谁说话算数」。

## 1. 权威等级（Authority Map）

```
产品事实源（唯一）
  └─ Suanming Preview PRD v1.2 东方时间文化档案微信小程序.md
       （由 D-001 裁决：preview-docs/ 冻结文档体系唯一充当产品事实源）

设计事实源
  └─ Suanming Preview UIUX Specification v1.0.md

工程事实源
  ├─ Suanming Preview Technical Architecture Specification v1.0.md   （分层与契约）
  ├─ CALCULATION_BASELINE_V1.md（FROZEN 专项权威）                    （确定性计算口径）
  └─ Suanming Preview Development Environment Baseline v1.0.md        （环境复现）

治理层（不是事实源，是「裁决 + 证据」）
  └─ governance/

执行层（自我声明「不是事实源」）
  ├─ Suanming Preview Developer Handbook v1.0.md
  └─ Suanming Preview Development Plan v1.0.md

已降级
  └─ 微信小程序开发大赛-开发计划.md  →  仅作「赛事策略参考文档」
```

冲突处理规则（Handbook §3，9 条）核心：**上位冻结文件覆盖下位计划**；
下位文档与上位规格冲突时，以上位为准并登记为问题，不自行改写。

## 5. 代码内文档注释规范

本仓库的代码注释承担了「事实源引用」职责，值得单独说明其体例：

| 注释内容 | 示例 |
|---|---|
| 文件级职责说明 | `miniprogram/lib/engine.js:1-4` |
| **权威依据引用** | `chinadst.js:10-15` 引用政府文件原文与京政办发[1988]17号 |
| **数据争议定论** | `chinadst.js:24-26` 明确百度百科「4 月 10 日」为误载，本表采 4/17 |
| **移植来源** | `solarlon.js:75-77` 标注移植自 `Vsop87Earth.kt:158-200` |
| **工程纪律/踩坑** | `engine.js:143-146` 解释为何统一 round Unix 分钟 |
| **不做什么** | `insight.js:8`「AI 只解释确定性事实，不参与任何历法计算」 |

修改这些模块时，**必须同步维护注释中的事实源引用**。

## 7. 父目录结构（仓库之外）

`suanming-preview` 是独立 git 仓库；它的**父目录**（工作目录根）不是 git 仓库，
存放的是治理层与上游交接物：

```
微信小程序开发大赛/
├── governance/          治理裁决与证据（D-001…D-005、HASH_CONTRACT_V1、B3/B6 证据）
├── _handover/           已校验的 Core 源码（Suanming-source-v0.21.0，715/715 SHA256 OK）
├── 小程序登记材料/       微信小程序备案登记填写卡等
├── 微信开发者工具安装包/  安装包（不入库）
├── *.md                 根目录冻结规格与审计报告（见 §2）
├── suanming-preview.zip 外部参考包（已判定「可复用仅 3 项，不可作 oracle」）
├── Suanming-source-v0.21.0.zip  上游 Core 原始压缩包（未改动）
└── suanming-preview/    ★ 本 Wiki 描述的工程实现仓库
```

> 读代码遇到「口径争议」时，答案通常在 `CALCULATION_BASELINE_V1.md`；
> 遇到「该不该做这个功能」时，答案在 `governance/B2_PRODUCT_SOURCE_DECISION.md`（D-001）。
