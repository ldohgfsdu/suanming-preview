# 04 · 历法引擎详解

本文描述 `miniprogram/lib/` 中的确定性历法内核。**全部为纯函数、无网络、无 AI 参与、无缓存**。

## 1. 时间基准链路

用户输入的「墙钟时间」到引擎内部的「绝对瞬间」经过三段换算：

```
用户钟表读数（1986–1991 可能是夏时制）
   │  civilTime.resolveChinaCivilTime()
   ▼
标准北京时间 UTC+8 的 (y, m, d, hour, minute)
   │  archive.computeArchive() 内部：jd = gregorianToJde(y,m,d)（该历日正午 UT）
   │                                        wallJde = jd + (wallHour − 20)/24
   ▼
绝对瞬间 wallJde（UT 儒略日）
   │  分段使用：
   │   ├─ 年柱 / 月柱 / 节气 bracket / 月龄 → 用 wallJde（真实绝对瞬间）
   │   └─ 日柱 / 时柱 → 用真太阳时校正后的「太阳钟」日期与小时
   ▼
历法事实
```

> `gregorianToJde` 返回该历日**正午 UT**，北京标准时 20:00 与其对齐，
> 因此减 20h 即得绝对瞬间（`archive.js:195`）。

## 2. `engine.js` —— 基础历法

### 2.1 儒略日换算

| 函数 | 说明 |
|---|---|
| `gregorianToJde(y, m, d)` | 公历 → JDN。带 1900–2100 范围校验，越界抛 `Error('range ' + y)` |
| `gregorianToJdeAny(y, m, d)` | 无范围校验版本，仅供节气跨年搜索内部使用 |
| `jdeToGregorian(jde)` | JDN → `{y, m, d, h}`。含格里历改革修正（`z >= 2299161`） |
| `isoUtc(jde)` | JDE(UT) → `YYYY-MM-DDTHH:MM:SSZ`。**先把 JDE 映射到 Unix 分钟再统一四舍五入**，天然处理 `23:59.5 → 次日 00:00`，避免手工分别 round 产生 `12:60:00Z` |

### 2.2 节气求解

```js
termJde(ord, year)          // 序数 0..23（0=小寒，3=春分，23=冬至）+ 年份 → 节气 JDE
termJdeNear(ord, jde)       // 就近搜索：在 year-1 .. year+1 三候选中取最接近的
solarTermResultAt(jde)      // → { prev, next, daysToNext }
```

求根策略 `solveLonWindow(target, lo, hi)`：

1. 初值用 `TERM_REF_MONTH` / `TERM_REF_DAY` 表中的近似日期
2. 窗口扩张：最多 12 次，每次 `a -= 30; b += 30`，用 `zcross()` 判符号翻转
3. 二分收敛：最多 60 次，收敛判据 `b - a < 0.0004` 天（约 35 秒）

节气目标黄经 `mod360(285 + ord * 15)`（小寒 285°，之后每 15°一个）。

### 2.3 干支柱

```js
dayPillar(jdn)    // 日柱：idx = ((54 + floor(jdn+0.5) − 2451545) mod 60 + 60) mod 60
yearPillar(jde)   // 年柱：以立春（ord=2）为界；立春前算上一年
```

日柱公式锚定 J2000.0（JD 2451545）为已知日柱，偏移 54。
年柱通过 `(ganzhiYear − 1984) mod 60` 取索引（1984 = 甲子年）。

### 2.4 均时差 EoT

```js
eotMinutes(jde)
// a = 2π/365 × (n − 1)，n 为年积日
// 229.18 × (0.000075 + 0.001868·cos a − 0.032077·sin a
//          − 0.014615·cos 2a − 0.040849·sin 2a)
```

这是 Meeus 的近似级数（秒级误差），对分钟级精度需求充分。

## 3. `solarlon.js` —— 高精度太阳视黄经

口径：太阳**视几何黄经**（地心、真春分点/平黄道 of date），
含岁差、章动、光行差、FK5 改正。

### 3.1 计算链

```
jdeUtc (UTC 儒略日)
  │  deltaTSeconds(yearFromUtcJd(jdeUtc))
  ▼
jde = utcJdToTt(jdeUtc)             ← TT = UT + ΔT/86400
T = (jde − 2451545)/36525           ← 儒略世纪
l0 = seriesValue(L, T×0.1)          ← VSOP87B 地球黄经级数（弧度）
pA = (5029.0966 + 1.11113·T − 0.000006·T²)·T·AS2R   ← 岁差（Meeus 21.6 经度 p 系）
s  = l0 + pA + π − 0.09033·AS2R     ← 太阳几何 + FK5 黄经改正
rR = seriesValue(R, T×0.1)          ← 日地距离（AU）
dp = nutationLongitudeArcsec(T)·AS2R ← 1980 IAU 63 项章动经度 Δψ
ab = (−20.4898/rR)·AS2R             ← 光行差
return mod360((s + dp + ab)·RAD)
```

### 3.2 必做的 TT 换算

VSOP87 级数在**力学时（TT）**基准下定义。若直接把 UTC JD 代入，
节气时刻会出现约 ΔT（≈2 分钟）的系统性偏移。这一点与 Core
`SolarTermCalculator.sunApparentLongitude` 接线一致。

### 3.3 ΔT 分段多项式

Espenak & Meeus（NASA TP-2006-214141），定义域 1900–2100，
域外**钳制到端点**（确定性，不静默使用错误模型）。分段：

| 年份区间 | 形式 |
|---|---|
| < 1920 | 4 次多项式，相对 1900 |
| 1920–1940 | 3 次多项式，相对 1920 |
| 1941–1960 | 含 `/233`、`/2547` 有理式 |
| 1961–1985 | 含 `/260`、`/718` 有理式 |
| 1986–1999 | 5 次多项式，相对 2000 |
| 2000–2100 | 世纪参数形式 `62.92 + 32.217c + 55.89c²` |

由 `tests/unit/solar-terms-accuracy.test.mjs` ST1–ST5 回归锁定。

### 3.4 与 Core 的关系

`solarlon.js` 的级数定义于 `sunEphem.data.js`，后者由
`scripts/gen-ephemeris.mjs` 从 IMCCE 官方 `VSOP87B.ear` +
Meeus ch.22 章动表**程序化生成**（代码生成，杜绝手抄错）。

**单一事实源**：`engine.solarLon` 只是 `solarlon.solarLongitude` 的转发
（历史命名保留），二者是同一个高精度实现，**不存在低精度生产路径**。
一致性由 `tests/unit/astronomy-audit.test.mjs` 的 A18 断言（<1e-9）钉住。
`solarLongitudeLow` 是 Meeus 低精度参考实现，仅供人工调试/对拍，
`sun.js` 与节气求解都走高精度。

## 4. `archive.js` —— 四柱与事实组装

### 4.1 月柱：五虎遁

```js
monthPillar(jde, ganzhiYear)
  ord  = findJieOrd(jde)                 // 只取偶数序（「节」，立春=2 … 小寒=0）
  zhi  = monthBranchFromOrd(ord)         // ((ord−2)/2 + 2) mod 12 → 寅月起
  yStem = (ganzhiYear − 1984) mod 10     // 年干
  yinStem = (yStem × 2 + 2) mod 10       // 寅月天干（五虎遁：甲己之年丙作首）
  stem  = (yinStem + ((zhi − 2 + 12) mod 12)) mod 10
```

月柱区间由**上一个「节」**决定，而不是公历月份的 1 号。
十二「中气」（奇数序）排在两节之间、不换月。

### 4.2 时柱：五鼠遁

```js
hourPillar(dayStemIdx, hour)   // hour in 0..23（23 与 0 皆子时）
  zhi    = floor((hour+1)/2) mod 12
  ziStem = (dayStemIdx × 2) mod 10        // 甲己还加甲
  stem   = (ziStem + zhi) mod 10
```

### 4.3 日界规则

```js
export const DayBoundaryRule = {
  CHANGE_AT_ZI: 'CHANGE_AT_ZI',          // 默认：23:00 换日
  CHANGE_AT_MIDNIGHT: 'CHANGE_AT_MIDNIGHT',
};
applyDayBoundary(y, m, d, hour, rule) → { y, m, d, hourForZhi, dayShifted }
hourStemDayStem(pillarDate, hour, rule, dayPillarObj)
  // CHANGE_AT_MIDNIGHT 且 hour >= 23 时，晚子时时干取「次日」日干
```

三矩阵测试（早子时 / 晚子时 / 午夜）由 `tests/unit/core-port.test.mjs` 覆盖。

### 4.4 真太阳时

```js
trueSolarToLocal(y, m, d, hour, lonDeg)
  jmin       = eotMinutes(jde) + 4 × (lonDeg − 120)   // 分钟
  solarHour  = hour + jmin/60
  dayShift   = floor(solarHour/24)
  canonHour  = ((solarHour % 24) + 24) % 24
  canonDate  = shiftDate(y, m, d, dayShift)
```

返回 `offsetMinutes / solarHour / dayShift / canonHour / canonDate / dayChanged / dateText`。
若校正后越出 1900–2100，`computeArchive` 内部 `canon` 置 `null`（显式降级，不伪造）。

### 4.5 双时间轴（移植 Core 的关键点）

`computeArchive` 内部分两条时间轴取柱：

| 柱 | 时间基准 | 理由 |
|---|---|---|
| 年柱、月柱 | 绝对瞬间 `wallJde` | 立春/「节」是绝对天文时刻，不受真太阳时影响 |
| 日柱、时柱 | 真太阳时校正后的**太阳钟**日期 + 小时 | 传统历法以太阳位置定日 |
| 节气 bracket | 绝对瞬间 `wallJde` | — |
| 月龄 | 绝对瞬间 `wallJde` | 朔望月相由真实瞬间决定，**不是当日正午** |

> 月龄在 V4 修正过一次：原来用固定该日正午 `jd`，导致时辰未知时的代表时刻不统一，
> 现统一按「当日北京时间午正」作代表时刻并走 `wallJde`。

### 4.6 五行 tally

```js
export const ELEMENT     = { 甲:wood, 乙:wood, 丙:fire, … };   // 天干五行
export const ELEMENT_ZHI = { 子:water, 丑:earth, 寅:wood, … }; // 地支本气五行
tally(ganArr, zhiArr) → { wood, fire, earth, metal, water }
```

**只统计「字面出现次数」**，不做任何强弱/喜用判断
（PRD/Guard 明确禁止旺衰、喜用、用神等词）。

### 4.7 月相

```js
newMoonJde(k)     // Meeus 新月级数（24 个周期项）
lunarAge(jde)     // → { newMoonIndex, newMoonJde, ageDays }
lunarPhase(a)     // 朔/娥眉月/上弦月/盈凸月/望/亏凸月/下弦月/残月
```

`lunarPhase` 的阈值分段（天）：`<1` 朔，`<4` 娥眉月，`<6.5` 娥眉月，
`<10` 上弦月，`<13.5` 盈凸月，`<16.5` 望，`<20.5` 亏凸月，`<23.5` 下弦月，
`<28` 残月，其余残月。

| `chang_ganzhi` | 四柱拼接串（仅展示用，**禁止入 hash**，见 HASH_CONTRACT §6.4 H-1） |

## 5. 农历表（`lunar.js` / `lunar-table.js`）

固定表每行 `[year, month, leap, startJDN, len]`：

- `year`：农历年
- `month`：农历月 1–12
- `leap`：1 = 闰月
- `startJDN`：该朔月初一的公历 JDN
- `len`：该朔月天数（29 或 30）

构建规则（`scripts/gen-lunar-table.mjs`）：

1. 朔时刻 `newMoonJde(k)`，月首公历 JDN = `floor(nmJDE + 0.5 + 8/24)`（北京时）
2. 中气 = 奇数 `ord`（`{1,3,...,23}`）
3. **含中气的朔月** → 月号 = 该中气映射（雨水→正月，春分→二月，…）
4. **无中气的朔月** → 闰月，月号取上一个正常月
5. 农历年 = 该月所属「正月」的公历年

工程纪律：表由天文算式推导，与黄金锚点对拍；
`day` 在「新月北京时刻临近子夜」时可能 ±1 偏差
（真实历法误差，非臆造），返回对象显式带 `approx: true`。

映射表（中气 ord → 农历月号）：

| 中气 | ord | 月号 | 中气 | ord | 月号 |
|---|---|---|---|---|---|
| 大寒 | 1 | 12 | 夏至 | 11 | 5 |
| 雨水 | 3 | 1 | 大暑 | 13 | 6 |
| 春分 | 5 | 2 | 处暑 | 15 | 7 |
| 谷雨 | 7 | 3 | 秋分 | 17 | 8 |
| 小满 | 9 | 4 | 霜降 | 19 | 9 |
| | | | 小雪 | 21 | 10 |
| | | | 冬至 | 23 | 11 |

`lunarMonthsOfYear(year)` / `lunarDaysOfMonth(year, month, leap)` 供 UI 三级选择器使用。

## 6. 日出日落（`sun.js`）

```js
sunTimes(y, m, d, lngDeg, latDeg) → { sunrise, sunset, noon, valid }
```

- `solarDeclination(jde)` = `asin(sin(ε)·sin(λ))·R2D`，ε = 23.44°
- 余弦判据 `cos H = −tanφ·tanδ`；`|cosH| > 1` → 极昼/极夜，`valid = false`
- 地方平太阳时正午 `12 − (lng−120)/15 − EoT/60`
- 返回 `HH:MM`（当地平均太阳时 LMT）

用途仅限「今日天时」卡片；**不参与任何四柱/节气计算**。
默认坐标北京 `(116.4074, 39.9042)`。

## 7. 夏时制（`chinadst.js`）

### 7.1 数据表（逐年政府文件确认，不套公式）

| 年 | 春拨（周日 02:00） | 秋拨（周日 02:00） |
|---|---|---|
| 1986 | 05-04（首年，准备期推迟） | 09-14 |
| 1987 | 04-12 | 09-13 |
| 1988 | **04-17**（当月第 3 个周日，非第 2 个） | 09-11 |
| 1989 | 04-16 | 09-17 |
| 1990 | 04-15 | 09-16 |
| 1991 | 04-14 | 09-15 |

### 7.2 墙钟状态机

```
classifyWall(y, mo, d, h, mi):
  ┌─ t < gapStart ──────────► STANDARD   （标准时 UTC+8）
  ├─ gapStart ≤ t < gapEnd ─► GAP        （02:00–03:00 不存在）
  ├─ gapEnd ≤ t < foldStart ► DAYLIGHT   （夏令时 UTC+9）
  ├─ foldStart ≤ t < foldEnd► FOLD       （01:00–02:00 出现两次）
  └─ t ≥ foldEnd ───────────► STANDARD
```

不依赖设备 tzdata（切换日期硬编码），避免设备时区库差异导致结果漂移。

### 7.3 解析规则

```js
resolveWallToInstant(y, mo, d, h, mi, { foldChoice })
  GAP    → { ok:false, reason:'dst_gap' }                    // 拒绝，不静默顺延
  FOLD   → foldChoice 缺省 → { ok:false, reason:'dst_fold_unresolved' }
           'earlier'（夏令时，+1h）/ 'later'（标准时）
  其他   → offsetMin = −480 − (DAYLIGHT ? 60 : 0)
```

### 7.4 时区-经度自洽降级契约

```js
assessLonTimezoneConsistency(placeLon, timezoneId)
  // 移植 Core SolarTime.kt:45 的 MAX_LONGITUDE_TZ_MISMATCH_DEGREES
  // |placeLon − 时区中央经线| > 60° → { degraded:true, reason:'lon_tz_mismatch' }
```

`timezoneCentralMeridian(zoneId)` 用 IANA representative longitude，
覆盖 UTC 全域主要偏移 + POSIX 风格 `Etc/GMT+8`（注意符号反转）。

## 8. 展示格式化（`display.js`）

| 函数 | 用途 |
|---|---|
| `fmtTermDate(utc)` | 用户层：设备本地 `M月D日 HH:MM` |
| `fmtTermLong(utc)` | 用户层：本地 `YYYY-MM-DD HH:MM` |
| `fmtTermUtc(utc)` | 技术层：原始 `UTC YYYY-MM-DD HH:MM`（关于页/说明） |
| `fmtDaysLeft(days)` | 自然语言 `X天X小时` / `X小时X分` / `X分钟` / `已到` |
| `fmtDaysLeftTechnical(days)` | 技术层：`4.51 天` |
| `fmtAgeDays(ageDays)` | 月龄 `1.6 天` |
| `fmtCoord(lng, lat)` / `fmtLng(lng)` | 坐标（统一 1 位小数，地名为主数字弱化） |
| `fmtTrueSolarMinutes(m)` | 真太阳时修正量，带符号 |
| `fmtClockTime(hhmm)` | 日出日落透传 |

**时区规则**：节气时刻在算法内以 UTC ISO 存在，用户层一律按设备本地时区显示
（不硬编码任何时区），技术层保留原始 UTC。
